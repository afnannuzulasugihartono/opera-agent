# Opera Agent

A private, local-browser control bridge.

- Lets MCP clients drive the user's own browser session through a strict allowlist of
  generic browser primitives.
- Returns structured results; the session never moves to a cloud browser.
- The extension holds generic primitives only: receive, validate, execute, collect, return.
  It may grow as rich as task-based work needs — including local real-time loops —
  as long as every primitive stays generic. Simple means clear boundaries and no
  dead code, not a small feature count.
- Site-specific behavior lives in server-side Supabase workflows, which hot-update
  independently of the installed extension. No per-site logic and no free `eval`
  ever live in the extension.

## Boundary

- [`AGENTS.md`](AGENTS.md) holds instructions: the rules, guidelines and requirements that
  bind every task, and the map of which document answers which question.
- [`README.md`](README.md) holds the explanation: what this is, what each directory does, how
  to run it, and that same map.
- A rule that changes what you may do lives in [`AGENTS.md`](AGENTS.md) and nowhere else.
- [`CONTRIBUTING.md`](CONTRIBUTING.md) says what a change has to look like when it arrives
  here, and how a reviewer reads it. It repeats no rule.
- [`CHANGELOG.md`](CHANGELOG.md) says what each release contained, and points at the notes.
- [`SECURITY.md`](SECURITY.md) is the private route for a vulnerability, where GitHub renders
  it; [`docs/security.md`](docs/security.md) holds the detail.

## Contract

| | |
| --- | --- |
| Protocol | `1` |
| Browser primitives | **36** allowlisted generic methods ([`extension/lib/protocol.ts`](extension/lib/protocol.ts)) plus device-local `watch.*`/`loop.*` async methods |
| Local MCP surface | **56** tools ([`local/mcp-server.ts`](local/mcp-server.ts)) - the operator's own signed-in Chrome, no cloud hop, plus the wallet that pays for the work |
| Distribution | Signed CRX3 self-updates from the update service |

## One command

```bash
npm i -g opera-agent-mcp
```

| | |
|---|---|
| `opera-agent-mcp local` | the everyday browser on this machine, over the loopback bridge |
| `opera-agent-mcp auth` | sign in once; the token stays beside this install |
| `opera-agent-mcp doctor` | print what is connected and what the plan allows |
| `opera-agent-mcp install` | register the extension with every Chromium browser on this Windows machine |
| `opera-agent-mcp uninstall` | remove the keys, the OperaAgent folder, and the package itself |

The local drive is metered where it happens: the local bridge calls the cloud once per session to open the meter and reads the plan from there, then enforces it locally and reports usage into the same daily count the hosted surface reads, so a command past the allowance answers `PLAN_LIMIT_REACHED` with the plan named. The gate lives in the bridge and in the plan's data in the database, never in readable client code. The package is
on the registry: `npm i -g opera-agent-mcp`, or from a clone with
`cd local && npm install -g .`. The full answer: [`docs/agent-call.md`](docs/agent-call.md).

Every number in that table is measured, not typed: `tests/docs/readme.test.mjs` reads the
primitives from the protocol, the tools from the local server's tool table,
and the edge functions from the directories that hold an `index.ts`. A number that
drifts fails the suite instead of ageing in the file.

## Layout

| Directory | Role |
|---|---|
| `extension/` | MV3 runtime — background worker, content scripts, popup, options |
| `shared/` | The one pure core both roads import — SERP parser, normalizer, VM semantics; no copy may drift, so local carries a pack-generated copy and the repo carries the source |
| `local/` | The local MCP server: CDP straight to the browser on this machine, plus the statement job (`local/lib/` is generated by `scripts/pack/pack-mcp.mjs`, never committed) |
| `hosted/functions/` | Deno edge: auth, billing, bridge, gateway, listen, runner, update, VM (8 deployed) plus `_shared/` — edge-runtime modules only |
| `hosted/migrations/` | SQL in timestamp order, never rewritten |
| `scripts/` | The machines, grouped by verb: `release/`, `pack/`, `verify/`, `dev/`, `bench/`, `proof/` |
| `tests/` | Fast suite is `npm test`; grouped by subject — `local/`, `hosted/`, `extension/`, `landing/`, `vm/`, `billing/`, `release/`, `shared/`, `surface/`, `tooling/`, `docs/`, `search/`; py gates stay at the root |
| `landing/` | The site Cloudflare Pages serves |
| `docs/proof/` | The record of real shipped runs |
| `docs/store/` | Generated Chrome Web Store form: `scripts/release/build-store-package.py` writes the manifest and the zip from `extension/` |

The map of every entry, every import rule, and the rules for what may be created where: [`ARCHITECTURE.md`](ARCHITECTURE.md), enforced by `tests/tooling/architecture.test.mjs`.
