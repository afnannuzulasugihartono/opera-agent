# Page Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a model the whole page: every meaningful element grouped into 17 classes with document coordinates, plus a full-document screenshot that falls back to readable tiles when one image cannot be carried or read.

**Architecture:** A classic content script, `extension/lib/page-map.js`, owns the classification table, the element projection and the pagination, so the rules are testable in Node without a DOM. `extension/content.js` scans the document once, caches per `documentId` + `mutationVersion`, and answers `page.read` with `view: "map"`. The hosted MCP adds one tool, `read_page_map`, that returns the scan flat, and `capture_page` learns to walk the document in tiles when the single full-document image is unreadable or larger than the wire allows.

**Tech Stack:** Node 22 (`node:test`), MV3 classic content scripts, Chrome DevTools Protocol `Page.captureScreenshot` with `captureBeyondViewport`, Deno + zod/v4 + MCP SDK on Supabase Edge Functions, Python Playwright harness for in-page proof.

**Spec:** `docs/superpowers/specs/2026-11-07-page-map-design.md`

## Global Constraints

- 17 classes, exact names and priority order: `button, choice, input, select, heading, link, media, iframe, picture, icon, table, list, form, region, separator, status, text`. One element, one class; the first matching rule wins.
- `rect` is in document coordinates (`getBoundingClientRect()` plus the scroll position at scan time), never viewport coordinates.
- A class pull: `offset` default 0, `limit` default 200, maximum 1000.
- Map cap: 20000 elements per document; beyond that the scan stops and says `truncated: true`.
- Device result cap: 512 KiB (`extension/lib/serialize.js`, `MAX_RESULT_BYTES`); a map pull never reaches it because the worker trims it first, and it must degrade, never throw.
- Full capture is the primary path. Tiles fire when the full capture fails (`SCREENSHOT_TOO_LARGE`, `SCREENSHOT_TOO_SMALL`, `BLANK_SCREENSHOT`, `CAPTURE_TIMEOUT`, CDP error) or when it succeeds unreadably (result scale < 0.2 or result width < 320 px).
- Tile strip height = viewport height, scale 1, document-coordinate clips, no scrolling of the user's page. Tiles are walked in slices because the device result is bounded.
- Primitive count stays **31**; the hosted MCP surface goes **34 -> 35** tools.
- Every tool output is `{ok, ...facts}`; every collection is an array under a named field; no fact is repeated at two levels; no field in use is renamed or removed.
- No `// WHY` blocks. A comment sits above a declaration, one line, and only where the code cannot say it.
- Every new or changed source file carries `@last-edited`, `@title`, `@state`, `@dependencies` in its first 8 lines.
- `extension/background.js` stays under 600 lines; a file in `extension/worker/` stays under 550.
- Gates: `npm test`, `npm run check`, and `py tests/browser_extension_test.py` for anything the extension does inside a page.
- Re-pins happen only through `npm run gates:refresh`, with the reason in the commit that moves the pin.
- Merge and deploy happen from `D:\GitHub\opera-agent` (the main checkout); no push and no PR without the human partner's word.

## Review Focus

- An empty or textless page: the skeleton must still answer with all 17 class entries (counts at 0), `totalElements: 0`, and no throw.
- A page that mutates between two pulls: the second pull must rescan (the cache is keyed by `mutationVersion`) and must never mix `order` values from two scans; `scannedAt` and `mutationVersion` are what let the model tell.
- A class larger than one pull: walking `offset` 0, 200, 400 ... must yield every element exactly once, in order, with no gap and no duplicate.
- An element below the fold: its `rect.y` must exceed the viewport height, and clicking it by `ref` after a scroll must still land.
- A page whose full capture is technically valid but unreadable (54 px wide): the capture must return tiles, not the 54 px image.
- A device result near 512 KiB: it must be trimmed with `truncated: true`, never answered with `Result exceeds ... bytes`.

- [ ] **Step 3: Implement `extension/lib/page-map.js`**

A classic script, the shape `extension/semantic-identity.js` already uses: an IIFE that sets one frozen global and returns early if it is already set. No DOM access, no `chrome.*`, no imports.

- `RULES`: an ordered frozen array, one entry per class in the table order. Each entry is `{class, tags: string[], roles: string[], inputTypes?: string[], needsHref?: boolean, minSide?: number, maxSide?: number}`. The `input` rule owns `input` and `textarea` with `inputTypes` naming the types that belong to `button`/`choice`; the earlier rules win.
- `classify(descriptor)`: lowercase `tag`; walk `RULES` in order; return the first class whose tags/roles/types/`href`/rendered side match. The rendered side is `Math.max(Number(width) || 0, Number(height) || 0)`.
- `projectElement(raw)`: build the common fields (`class, ref, tag, role, text, label, rect, order, depth, regionId, visible, actionable, disabled, logicalId, stableKey`), then copy every field named in `CLASS_FIELDS[raw.class]` from `raw`, then drop every entry whose value is `undefined`, `null` or `''`.
- `paginate(elements, offset, limit)`: clamp `offset` into `[0, total]`, clamp `limit` into `[1, 1000]` with a default of 200, slice, and compute `hasMore`/`nextOffset` (`null` at the end).
- `unionBox(elements)`: the union of every `rect`, or `null` when there is none.
- `summarizeClass(name, elements)`: `{class, count, bbox}`.
- Header in the first 8 lines: `@last-edited: 2026-11-08 UTC+7.`, `@title: page-map — the rules that name an element and page it out, with no DOM in sight.`, `@state: the seventeen classes in rule order, the field each class adds, the projection, and the pull.`, `@dependencies: none.`
