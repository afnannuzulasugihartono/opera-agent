# run_task Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One MCP tool `run_task { task, tabId?, confirm?, requestId, timeoutMs }` that takes a natural-language task, has the device compile it (one device-local model call) into a read-only VM program or a confirmed adhoc write graph, executes it over the existing 31 generic primitives, verifies the result, and returns a per-node trace.

**Architecture:** The MCP server validates input, recalls matching skill lessons via `opera_skill_recall`, and enqueues a single `task.run` command to the device with `requestId` for idempotency. The device (`extension/worker/task-runner.js` + new pure `extension/lib/task-compile.js`) builds a capped prompt (`buildPlanRequest`), makes one model call (`composeModelPlan`, injectable fetch), parses `{ mode, program|graph, verify }`, gates it (`compileGoalPlan` / `compileAdhocGraph`), executes through the existing VM/adhoc paths, verifies via `page.find`/`page.read`, and returns the trace. The server then saves the lesson via `opera_skill_save`. No new browser primitives, no per-site code, no eval.

**Tech Stack:** TypeScript Deno edge functions (`supabase/functions/opera-agent-mcp/`), MV3 extension JS (`extension/`), pure shared modules (`extension/lib/`, `lib/`), Node test runner (`node --test` via `npm test`), gates via `npm run check`.

**Spec:** `docs/superpowers/specs/2026-10-30-run-task-design.md` (approved 2026-10-30; stages: Tahap 1 read lane + Tahap 2 write lane are both in this plan, Tahap 3 direct-push enqueue and Tahap 4 chat UI are explicitly out of scope).

## Review Focus

1. `task` longer than 1200 chars or non-string → rejected before enqueue (Task 2 test).
2. Reused `requestId` → no second execution (Task 2 + Task 10 tests).
3. `mode: "write"` without `confirm: true` → refused with a code, nothing registered (Task 4 + Task 8 tests).
4. Model not configured → `MODEL_NOT_CONFIGURED` before any network call (Task 5 test).
5. Verify clause not met → answer carries `verify.ok: false` with evidence, never reported as success (Task 7 test).
6. Compile refusal (owned field / non-allowlisted method / over budget) → code returned, nothing executed (Task 4 test).
