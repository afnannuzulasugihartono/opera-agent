## THE ASK, VERBATIM (paraphrased)

"Bump the version automatically - without the agent editing everything by hand, all of it must stay in sync." The 1.6.48 release took a manual pass over fifteen files, a hand re-pin of `gates.lock`, and a hand recompute of the frozen digests; a clock left behind read as a broken release until CI caught it (it did, three times). The ask is one command - one button in the Actions tab - that moves every clock and proves they all landed together before a human decides anything.

## DESIGN

### `scripts/bump-version.mjs` - the engine

- Input: exactly one argument, `node scripts/bump-version.mjs <version>`, `^\d+\.\d+\.\d+$`; refuses anything else, and refuses when the tree is dirty (it writes into git-tracked files, so the diff it makes must be reviewable in isolation). Reads the current version from `extension/manifest.json`.
- **Rewrite enumeration is explicit, not a grep.** Each entry is `{ file, pattern, replacement }` and each pattern must match exactly once; a miss is a hard error naming the file - the enumeration is stale and the run stops before writing anything. The enumeration covers every row in the table above **except** histories.
- **Four parts rule:** `store/store-manifest.json` rewrites to `<v>.0` and nothing else accepts four parts.
- **Handoff narrow rewrite:** exactly three anchored substitutions in `docs/handoff.md` - the State bullet's `releases/<old>.md` link (twice on the same line), its `at the <old> release commit` phrase, and its `everything <old>` phrase - nothing else in the file moves; the 0h-style shipped entries keep their historical version.
- **Recomputed pins:** the script rewrites `tests/helpers/boundary-locks.mjs` for the three LF-normalized blob SHA-1s it pins (`manifest.json`, `index.ts`, `tools.ts`) and prepends a `// WHY these three were re-pinned on <today>: the release bump rode them; nothing else in those files moved.` block above the export (comments live outside bodies). The `sourceSha256` in `tests/fixtures/mcp-contract-v1.json` is recomputed with `tests/helpers/canonical-source-hash.mjs`. Then `npm run gates:refresh` moves `gates.lock`.
- **Scaffold:** writes `docs/releases/<version>.md` from a template (title, today's date, three sections: WHAT REACHED THE SURFACE / WHAT CHANGED FOR CALLERS / WHAT IT COSTS THE READER, each carrying the version and the commit list since the previous release-note commit), and inserts one `CHANGELOG.md` row with the same date and a link. The scaffold is deliberately a skeleton - the reviewer fills the prose; nobody pretends a script can write "read_page_map is gone" honestly.
- **Verdict before exit:** runs `npm test` and `npm run check` itself; on failure the run is red and the PR is not opened. `--dry-run` prints the diff stat and stops.

### `.github/workflows/release-bump.yml` - the button

- `workflow_dispatch`, one input: `version` (required, `^\d+\.\d+\.\d+$`).
- Job on `ubuntu-24.04`, Node `22.20.0`: checkout `main` → verify input → run `node scripts/bump-version.mjs <version>` → it runs gates → commit on branch `release/<version>` with message `release: <version> - version bump` (branch is created fresh; a stale local ref is deleted first) → push → open a PR titled the same, whose body lists every file rewritten, every pin moved with its reason, the scaffold file, and a checklist for the reviewer (prose in the release note, handoff 0h entry, tool-count decisions if any).
- **It stops there.** No squash-merge, no `deploy-functions.yml`, no `publish-npm.yml`, no `publish-crx.yml`, no `deploy-site.yml`, and the workflow never writes to `main` directly. Merge stays the human decision and the deploys stay deliberate dispatches.
- Permissions: `contents: write` and `pull-requests: write`; nothing else. One concurrency group `release-bump`; a second dispatch queues, never cancels a run mid-bump.

### `tests/bump-version.test.mjs` - the never-again-stale gate

Walks every tracked text file and extracts every `1\.\d+\.\d+(\.\d+)?`:

- equal to the manifest's current version (or its 4-part form), or
- under allowlisted paths: `docs/releases/**`, `docs/superpowers/**`, `CHANGELOG.md` (historical rows), `docs/handoff.md` (prose history beyond the two rewritten anchors), `archive/`, and `tests/helpers/boundary-locks.mjs` (re-pin comments are per-version history by construction), or
- a re-pin whose recorded reason names this release, verified by the boundary-locks gate itself.

Anything else is red with the file and line. The test is the reason "all in sync" stays true without a human's vigilance: a new version reference added anywhere outside the enumeration and outside allowlists fails CI on the next PR that carries it.

### What is deliberately absent

- **No direct-to-main push.** No merge, no deploy dispatch, no CRX re-sign. The button prepares; the human decides.
- **No tool-count rewrite** (39 → 40 was a reviewed decision in 1.6.47 and again in 1.6.48; nothing here renumbers it, and the FROZEN digests do not move on a version bump by construction).
- **No rewriting of prose history** and no mass sed; the enumeration names its files.
- **No second implementation.** The local human path and the workflow path both call the same `scripts/bump-version.mjs`; there is no chance of the two disagreeing.
- **Nothing in `gates.lock` for the new script itself** - the acceptance surface it changes is pinned by the gates it refreshes; adding a pin for it would pin a mover.

## TESTING

- `tests/bump-version.test.mjs` runs against the real tree (like the rest of the suite): after any bump, zero stray references.
- `scripts/bump-version.mjs` carries its own unit seam - the rewriter takes `{ file, pattern, replacement }` lists and a root directory, so the rewrite/failure modes are testable on a synthetic tree in a `tmp` dir: exactly-once match enforced, no-match hard error, CRLF preserved on rewrite, 4-part rule, and refusal when a listed file does not contain the expected version.
- The gates themselves: `npm test`, `npm run check` after the bump must be green with zero manual edits - that is the acceptance test for the whole tool.
- A dry-run on `main` at e6fd9301 must report exactly the table above and exit 0 without writing anything.
