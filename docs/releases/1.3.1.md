# Opera Agent 1.3.1

Status: stable production release under the existing signing identity.

## Fixed

- Background trusted click, fill, key, and coordinate pointer input temporarily call CDP `Emulation.setFocusEmulationEnabled` while dispatching input.
- Focus emulation is disabled in a `finally` path immediately after each action and never calls tab activation or window-focus APIs.
- The result reports whether focus emulation was supported and used, allowing acceptance tests to distinguish the enhanced path from compatibility fallback.

## Safety and compatibility

- Extension ID remains `ohbbpamcljckmjhcpkcmefdobkoeaick` and protocol remains 1 with 25 allowlisted primitives.
- Existing pairing and the 1.2.0 rollback artifact are retained.
- Foreground pointer behavior and structured `FOREGROUND_REQUIRED` rejection are unchanged.
- Sensitive fields, uploads, internal pages, bounded input, deadlines, and result-size enforcement remain local.

## Production acceptance

- All 39 unit tests, static checks, Deno checks, Python compilation, isolated Opera focus tests, and isolated live-Google-Maps tests passed.
- The signed CRX updated the installed extension in place with the same ID and preserved pairing; its production heartbeat reported version 1.3.1, protocol 1, and 25 capabilities.
- On the installed Opera profile, a seven-step Google Maps burst (`read -> find -> click -> wait -> fill -> key -> read`) completed all steps in 291.1 ms of browser execution and 767 ms queue-to-result.
- Background click, fill, key, and coordinate click reported `focusEmulated: true`; the target tab remained inactive before and after the run while Google Maps loaded the restaurant results and opened a selected result.
- Foreground pointer input against the inactive target returned `FOREGROUND_REQUIRED`, confirming that foreground safety was not weakened.
- MCP Edge Function version 10 is active. Health and OAuth protected-resource metadata return HTTP 200, and an unauthenticated MCP request returns HTTP 401.
