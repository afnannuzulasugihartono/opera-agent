# Opera Agent 1.6.2

Status: signed offline forward-rollback candidate. It has not been uploaded or
activated in production.

## Purpose

Opera will not automatically install a lower version after updating to 1.6.1.
This artifact provides a higher-version rollback that restores the accepted
1.6.0 extension behavior if R8 production acceptance fails after update.

## Exact source basis

- Accepted source tag: `v1.6.0`.
- Source commit: `96ef1cfdbecc7c5c0e40486b6378501db606b84d`.
- `background.js`, `content.js`, and every other behavior-bearing extension file
  match that tag byte-for-byte.
- Only the packaged version strings in `manifest.json`, `lib/protocol.js`, and
  `popup.html` change from 1.6.0 to 1.6.2.
- Protocol remains 1, browser capabilities remain 26, the update URL is
  unchanged, and the manifest key is unchanged.

## Verification

The accepted `v1.6.0` controlled-browser harness was run against the prepared
1.6.2 extension with only its two version assertions updated. It passed,
including Protocol 1 / 26 capabilities, network and browser restart reconnect,
20/20 burst stability, sensitive/private capture guards, and 55-command
background-focus preservation.

## Release gate

This artifact must remain offline until an independent audit returns PASS for
the complete procedure. Before activation, insert 1.6.1 and 1.6.2 as inactive
immutable rows and verify database-decoded hashes, sizes, identities, and that
signed 1.6.0 remains the sole active row. If post-update 1.6.1 acceptance fails,
atomically activate 1.6.2; merely reactivating 1.6.0 cannot downgrade an already
updated browser.
