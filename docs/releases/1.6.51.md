# WHAT REACHED THE SURFACE

The browser half is TypeScript; the emitted content scripts strip the module marker so MV3 can load them as classic scripts. Before this, a classic content script with a top-level `export` is a SyntaxError in every tab it is injected into - that failure is now impossible to ship.

The tab an agent is holding shows a small `Opera Agent` chip in the corner. The worker remembers which tab it is working on for as long as it is active, the chip renders from that memory, and it is gone the moment the agent stops. The default is on; `Tandai tab yang dipegang agent` di popup mematikan.

`armWatchersForTab` refuses a missing tab instead of casting `undefined` to `number`. A malformed arm no longer reaches the page.

# WHAT CHANGED FOR CALLERS

- `armWatchersForTab(tabId)` returns `ARM_FAILED` when the tab is genuinely missing; no caller that passed a valid tabId is affected.
- `oa_chip_enabled` in `chrome.storage.local` toggles the chip; unset means on. Calls that hold a tab show the mark briefly and then the agent releases it.
- Nothing else moved; every tool speaks the same shapes as 1.6.50.

# WHAT IT COSTS THE READER

None. This is a completion release: the extension runs the same TypeScript it was already written in, the pipeline does not flake on fresh runners, and two small pre-existing failure modes were caught in the migration and closed.
