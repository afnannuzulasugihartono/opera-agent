# WHAT REACHED THE INSTALLER

**`npm i -g opera-agent-mcp` is now the whole install.** On Windows,
the package detects the Chromium browsers present and writes one
per-user registry key per browser pointing at the public update
manifest. On the first browser start, the browser installs the extension
itself — no Web Store review, no download dialog, no manual step. A
verified copy of the build (`opera-agent.zip`, sha256 checked against
the `x-opera-sha256` header of the update endpoint) is kept at
`%LOCALAPPDATA%\OperaAgent\<Browser>\` for anyone who needs the
manual path, plus a README that tells the whole story.

**`opera-agent-mcp uninstall` is the whole un-install.** It deletes the
three keys, `%LOCALAPPDATA%\OperaAgent\` (keep the pairing file with
`--keep-pair` if you want it), and uninstalls the package itself. The
registry-installed extension leaves the browser on the next start —
verified 2026-11-12 for Chrome 153.0.8010.36, Brave 157.1.99.56 and Edge
in isolated throwaway profiles. Developer-mode copies still ask for one
click at `chrome://extensions`.

**Only the npm package changed.** The extension, the update manifest,
the CRX, the store listing and everything server-side stay at 1.6.44;
nothing about the browser build moved in 1.6.46.

# WHAT IT COSTS THE READER

Nothing on a machine whose owner opted in by running the command. The
`postinstall` hook never fires in CI, never fires on non-Windows, and
never turns an npm install red; `OPERA_AGENT_NO_INSTALL=1` opts out
entirely. The everyday profile is never written to, and the one binding
step (OAuth sign in) keeps being a human's, deliberately.
