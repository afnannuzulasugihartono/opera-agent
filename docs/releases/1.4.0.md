# Opera Agent 1.4.0

Status: stable signed release under the established extension identity.

## Added

- `page.capture` and MCP `capture_page` provide bounded JPEG viewport or crop captures of an explicit HTTP/HTTPS tab through target-tab CDP without activating the tab or focusing its window.
- Adaptive quality and scale reduction enforce a 220 KiB decoded-image ceiling and maximum output dimensions of 1600×1200; normal defaults are quality 60 and 1280×900.
- SHA-256 comparison and a 750 ms, eight-entry memory cache suppress retransmission when `previousHash` matches.
- Blank all-white/all-black frames return `BLANK_SCREENSHOT` rather than misleading the model.
- The popup lets the user mark the current tab private for vision.

## Privacy and security

- Capture is blocked for internal pages, incognito tabs, user-private tabs, file inputs, and visible password, OTP, PIN, verification, or payment fields.
- The sensitive-surface scan covers the top document and embedded frames and fails closed if embedded-frame privacy cannot be verified.
- The extension stores captures only in a short-lived memory cache. The dedicated Supabase await function returns image data once and atomically replaces the database value with hash/size metadata; timeout cancels the command so a late result cannot persist.
- MCP returns native image content and excludes base64 from structured metadata.
- Protocol remains 1 and no arbitrary JavaScript, unrestricted CDP, desktop capture, or continuous streaming capability is exposed.

## Production acceptance

- The installed Opera profile updated in place from 1.3.1 to 1.4.0 with the same extension ID and preserved pairing. Its heartbeat reports protocol 1 and all 26 capabilities.
- Supabase migration `opera_agent_adaptive_screenshot` is applied and MCP Edge Function version 11 is active. Health and OAuth metadata return HTTP 200 while unauthenticated MCP calls remain HTTP 401.
- An inactive live Google Maps tab produced a valid 1280×643 JPEG of 193,320 bytes in 2,092 ms total without changing the user's active tab.
- The 257,760-character base64 payload was returned once, atomically replaced with 120 characters of hash/size audit metadata, and a second read returned `CAPTURE_RESULT_CONSUMED`.
- A connected ChatGPT conversation discovered and invoked `capture_page` twice on inactive Google Maps tab `584940597`. The first call returned a real 1484×746 JPEG (200,473 encoded bytes after adaptive quality reduction from 70 to 40) with SHA-256 `20c641c71cb3cfe927cdb56b1d73991ae36f30ad12b8f4934c9434671cc48354`.
- The second call supplied that hash as `previousHash`, returned `unchanged:true`, and did not retransmit duplicate image content. Google Maps remained inactive and the ChatGPT tab remained active throughout.
- Visual inspection exposed canvas-rendered map labels absent from the comparison DOM read, confirming that capture provides materially different information rather than duplicating `page.read`.
- Production command rows retain only scrubbed hash/size metadata after image delivery; the accepted capture is recorded as `scrubbed:true` with 200,473 encoded bytes.
