# Opera Agent 1.4.0

Status: signed release candidate under the established extension identity; not yet active in production.

## Added

- `page.capture` and MCP `capture_page` provide bounded JPEG viewport or crop captures of an explicit HTTP/HTTPS tab through target-tab CDP without activating the tab or focusing its window.
- Adaptive quality and scale reduction enforce a 220 KiB decoded-image ceiling and maximum output dimensions of 1600×1200; normal defaults are quality 60 and 1280×900.
- SHA-256 comparison and a 750 ms, eight-entry memory cache suppress retransmission when `previousHash` matches.
- Blank all-white/all-black frames return `BLANK_SCREENSHOT` rather than misleading the model.
- The popup lets the user mark the current tab private for vision.

## Privacy and security

- Capture is blocked for internal pages, incognito tabs, user-private tabs, file inputs, and visible password, OTP, PIN, verification, or payment fields.
- The sensitive-surface scan covers the top document and embedded frames and fails closed if embedded-frame privacy cannot be verified.
- The extension stores captures only in a short-lived memory cache. The dedicated Supabase await function returns image data once and atomically replaces the database value with hash/size metadata; timeout cancels the command so a late result cannot persist.
- MCP returns native image content and excludes base64 from structured metadata.
- Protocol remains 1 and no arbitrary JavaScript, unrestricted CDP, desktop capture, or continuous streaming capability is exposed.

## Verification before production

- All 40 Node tests, static checks, Deno type checks, and Python compilation pass.
- The full browser integration suite passes in controlled Chromium and isolated real Opera.
- Both runs preserve active-tab/window focus while capturing an inactive canvas page and verify crop bounds, hash reuse, image-size limits, blank-frame rejection, main-frame and embedded-frame sensitive-field blocking, user-private blocking, reconnect, and restart behavior.
