# Opera Agent 1.2.0

Status: stable production release under the existing signing identity.

## Added

- `browser.burst` for 1-8 sequential page actions on one tab through one durable relay command.
- Supported actions: read, find, click, fill, key, scroll, wait, and pointer.
- `run_browser_burst` as a focused MCP tool with strict discriminated schemas.
- Per-step results/timings and explicit partial-failure reporting.
- Lazy debugger attachment reused within a burst and detached at completion.

## Safety boundaries

- Protocol remains version 1 and the extension ID remains `ohbbpamcljckmjhcpkcmefdobkoeaick`.
- The public allowlist increases from 24 to 25 primitives.
- Bursts cannot change tabs, navigate, open or close tabs, loop, branch, nest, or execute arbitrary code.
- Maximum eight steps, 12 seconds total, 256 KiB of results, and stop on the first failed step.
- Existing password, OTP, payment, file-upload, focused-tab, and viewport protections still apply locally.

## Verification

- All Node unit/static tests and repository checks pass.
- MCP Edge Function passes Deno type-check with its pinned function configuration.
- Full isolated real-Opera regression passes under the established extension identity.
- Signed CRX3 was built with extension ID `ohbbpamcljckmjhcpkcmefdobkoeaick` and SHA-256 `bdc687b07a982c140803c8279c462a64fbe541423ddc1cbbe4b9ffb9324e64c8`.

## Production acceptance

- The method-registry migration is applied and `browser.burst` is enabled with a 12-second timeout; the older `browser.plan` experiment remains disabled.
- MCP Edge Function version 8 is active. Its health and OAuth protected-resource metadata respond correctly, while an unauthenticated MCP request receives HTTP 401.
- The private update channel serves the signed 1.2.0 CRX with the documented checksum. Opera updated under the same extension ID and preserved pairing.
- The production device reports version 1.2.0, protocol 1, and all 25 capabilities.
- A production three-action burst (`read`, `find`, `wait`) completed all steps in 7.6 ms locally and 613 ms queue-to-result. The temporary acceptance tab was then closed successfully.
- The first acceptance attempt against the protected `opera://extensions` page stopped safely before executing page actions, confirming the HTTP/HTTPS boundary.
- Signed releases 1.1.1 and 1.1.0 remain inactive in the private release registry for rollback; the previous MCP deployment versions remain available through Supabase deployment history.
