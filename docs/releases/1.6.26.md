# WHAT REACHED THE BROWSER

The local bridge link now proves itself before every call, and heals itself when
it stops answering.

Chrome retires an MV3 service worker thirty seconds after the last event and
keeps its WebSocket open anyway: the browser answers protocol-level pings in the
network layer while every frame that arrives goes to a message loop that stopped
existing. Observed live as a link that had answered nine pongs in a row and then
ignored a tab listing for thirty seconds, with dials climbing and messages at
zero.

So the worker now speaks. A frame goes out every fifteen seconds, which is the
traffic that keeps it alive, and the local side answers it in JavaScript rather
than at the protocol layer, because only a frame tells the truth about whether
worker code is still running. A ping nothing answers past thirty seconds makes
the link deaf, and a deaf link is thrown away and redialled.

Every local call now asks the cheap question first, and the extension recycles
links that sit idle past its own alarm. `browser.ping` reports the dials, the
messages, the replies and the socket state, so a link that is dying is visible
in the answer instead of inferred from a timeout. A local request retries once
after dropping a silent link rather than failing the caller's work.
