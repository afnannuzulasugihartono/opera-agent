# WHAT REACHED THE BROWSER

**The popup is a control panel now, not a form.** It answers the one question
the reader came for - is it connected - in one firm line, on a dark surface, and
everything else sits under that answer: the facts of the device, the controls,
and the doors out.

**It tells you when the version it runs is behind the one the server serves.**
Chrome updates an installed extension on its own, but only when it was installed
as a signed package: an extension loaded unpacked never asks the update service,
so the number on the card simply stands still and nobody can tell whether the
product is broken or the install is. The popup asks the update service which
version it serves, compares the two as numbers, announces the newer one, and
offers the button that fetches the signed package and opens the page where it is
dropped in.

**The doors out are in the menu:** the dashboard (the device list, the history,
the balance), the documentation, and the signed package that updates itself. A
popup that can only report cannot act, and a person who opens it with a problem
needs both.

# WHAT THIS RELEASE COULD NOT HAVE SHIPPED WITHOUT

**The measurement that named the cause.** The update service records every
request it answers, with the browser that made it. Every request in that record
came from a command line; the browser never asked for the manifest at all, and
the only browser requests were the CRX file the download page hands over. That
is the signature of an unpacked install: Chrome has no updater to poll with, so
it never asks, and pressing Update changes nothing.

The service was never the problem. It answered with the right manifest, the
right version and the right bytes, and the package it served was checked against
the key the manifest names before it was published.
