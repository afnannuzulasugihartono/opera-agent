# WHAT REACHED THE BROWSER

**The agent can pull an update the way `git pull` does.** Two hosted tools.
`check_update` answers what the device runs against what the update service
serves. `apply_update` asks the device to write the newest build over the
folder the reader allowed, and restart. The update page can be closed at any
time; nothing holds a connection that depends on it, and nothing reopens it.

**The update was asked of the wrong endpoint, and never happened.** The
served-version check read the health page of the update service, which answers
for the legacy extension and has said version 1.0.1 for years. Against it every
comparison answered "not newer": the popup hid the button, the timer wrote
nothing, and an extension that shipped its own updater could not update itself.
The version now comes from the archive this extension is updated from: a HEAD
on the download carries it in a header, and when the header cannot be read, the
build's own manifest decides - it is signed by the same key and names the
version it serves. The update service names that header as readable from
another origin, so a browser may read it too.

**The popup is one flat list, in the reader's language.** The doors are
Dashboard, Pairing, Update and Documentation; the update is the one amber row;
there are no cards, no bezels and no explanation lines under the buttons.
Every word is localized (Indonesian and English, selected by the browser's
language) from one table, and the next language is one more table.

**The toolbar carries the site icon.** The green cursor on the dark tile,
drawn by `npm run icons` from the same path the site uses, and the action
names it; the toolbar no longer shows the browser's generic glyph.

**The relay may run exactly the methods the extension serves.** The server's
own list of the methods it may run had drifted: `statement.download` and
`statement.manifest` were missing, so the tools that call them were refused by
name, and `page.read` and `page.capture` were cut short by a budget shorter
than the contract gives them. The list is now seeded from the contract, and a
test pins the seed to it, method for method.

# WHY THIS IS WORTH A RELEASE
# The update path shipped dead: the version question was asked of the one arm
# that cannot know it, and the update ritual asked for a download and a reload
# every release. The popup, the gate page and every icon were redrawn around
# the one thing the reader came for. Both were found by driving the product
# end to end, not by reading it, and both are answered in this build.

# WHAT IT COSTS THE READER
# One time only: the build that carries the pull does not exist on devices
# running 1.6.40 or older, so this release still needs one manual folder
# overwrite and one reload - or the popup's one-click "Unduh". After that, the
# worker pulls the next ones itself, like `git pull`.
