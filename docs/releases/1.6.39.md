# WHAT REACHED THE BROWSER

**The version moves by itself, after one permission.** A browser never updates an
extension that was loaded from a folder: it has no updater for one, so the version
stands still and the reader is left with the same ritual every time - download,
extract over the folder, press reload.

The reader gives the one thing that turns the ritual into nothing: permission to
write into the extension's own folder. The popup asks for it once, the folder is
remembered for that folder alone, and from then on the extension asks the update
service what it serves every thirty minutes, writes a newer build over the folder
and restarts itself. Nothing to click, nothing to download, nothing to extract.

**The write is checked before it happens.** The folder is the reader's own
installation, so a wrong file there breaks their browser until they notice. The
build is read first, and it is only written when it carries this extension's
name and a version higher than the running one. A build that is not ours is
refused, and a path that walks out of the folder is refused.

**The popup says where the permission stands.** A version that does not move was
a mystery with no handle on it. The popup now says whether the folder is allowed,
whether the browser dropped the permission after an idle spell, and it offers the
reload that finishes an update by hand when the reader wants it.

# WHAT THIS RELEASE COULD NOT HAVE SHIPPED WITHOUT

**The proof is bytes, not a promise.** The reader is not asked to trust the
feature; the test builds the archive the update service serves, reads it with the
same reader the extension uses, and writes it into a folder that records what it
was given. The same test proves the two refusals: the same version writes
nothing, and a build that is not ours never reaches the disk.
