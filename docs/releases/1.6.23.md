# WHAT REACHED THE BROWSER

The device can now report what it is doing while it is doing it.

Until this release the MCP edge function was stateless: every request built a
fresh server and transport, enqueued a command, and blocked until the device
finished it. The device knew what happened in between and had no way to say so,
so an eight-step burst or a twenty-second workflow arrived as one opaque blob at
the end.

Three pieces carry it:

- **`opera_command_events`.** A command's events, with a cursor. The wait
  function returns the instant rows appear rather than at a deadline — measured
  at 4.48ms with rows present against 802.7ms against an 800ms budget when there
  are none — and reports the command's status on the same pass, so the consumer
  needs one call rather than two.
- **The device emits `received`, `step` and `done`.** The emit is deliberately
  not awaited. An awaited emit inside the burst loop would add a network round
  trip to every step of every burst, which is the exact latency the channel
  exists to remove.
- **The transport streams.** `enableJsonResponse` was `true` since the first MCP
  commit in September, with no reason recorded beyond the SDK's own example.
  Against a real MCP client running the same four-step tool, that setting
  produced **zero** progress notifications. Turning it off produced four, spread
  across 917ms, arriving as the work happened, with total time unchanged.

This is a visibility release, not a speed one. Streaming the transport was never
going to make the round trip faster: the device already parks inside a long-poll
whose tail is 100ms. What was missing was that nothing could be seen until the
end.

# WHAT REACHED THE SERVER

An event envelope reaches a model's context, so the channel that writes one is
treated as an untrusted input surface rather than a log.

`opera_emit_command_event` authenticates the device through the same
`opera_auth_device` helper the claim path uses, refuses a command whose
`device_id` is not the caller's, and matches the event kind against a fixed
allowlist instead of storing whatever string arrived. The bridge refuses a
malformed uuid, an unknown kind, and an envelope over 16 KiB.

Probed against the live database with a temporary device: its own command was
accepted, another device's real command was refused with `Command not found.`,
and zero rows landed in the foreign command's stream.

Both functions carry their full argument type list in order. A mismatched list
does not replace a function, it creates a second overload, and PostgREST then
cannot resolve a named-argument call to either — which is how
`opera_claim_next_wait` was deployed once with a reordered parameter list and
broke the extension's pull loop until `pg_proc` was read by hand. Exactly one
overload of each new function exists.

# WHAT THIS RELEASE COULD NOT HAVE SHIPPED WITHOUT

The tests for the consumer loop missed a mutation.

Six mutations were written to check the suite bites. Five were caught and one
was not: removing the deadline check passed, because no test ever exercised a
command that never terminates. A loop that had lost its deadline would have
spun forever, undetected, against a database. The test exists now, and the
mutation is caught.

Two smaller things are worth recording because they were wrong in the same way.
Three bridge tests initially passed *vacuously*, through the unknown-action
default, and were only meaningful once each was re-checked for the reason it
gives rather than the status code it returns. And a module-level variable was
the obvious way to carry the caller's progress emitter into a tool handler —
it would have raced across concurrent requests. `AsyncLocalStorage` carries it
instead, which was checked with two overlapping requests, each getting its own
store.

The SonarCloud quality gate on the merge that carried this read 3.8% duplication
on new code against a 3.0% threshold. Measured rather than guessed: all 28
duplicated lines are in the two migrations, which necessarily restate the
function they supersede because this repository does not edit an applied
migration in place. Every line of new application code measures zero. The gate
did not pass, and the honest response was to say so rather than cut correct SQL
to satisfy a percentage.
