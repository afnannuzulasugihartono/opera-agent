# @title: 1.6.34 - the local bridge retries once its socket drops.
# @state: the release note for the version now shipping.
# @dependencies: none.

When the loopback bridge drops its WebSocket with this worker (any restart of the local process, any reload, any silent network blink), the worker kept `running` as `true` forever and never tried to connect again - so a browser that lost its link stayed dead until Chrome reinstalled it.

The bridge link now reads the socket lifecycle explicitly: `connected` opens the link; every other state that ends the conversation (`reconnecting`, `rejected`, `stopped`) closes the link. The existing alarm retries every thirty seconds once the link is allowed to try again, so the browser that dropped its socket is picked up without a browser restart.
