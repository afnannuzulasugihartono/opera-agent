# WHAT REACHED THE SURFACE

Two tools answered:

**`dump_page`** - the whole page as one structured object, not one viewport at a time. Text pages by `offset` and `limit`, with `truncated` and `nextOffset` telling the caller exactly where to continue. Headings carry their level and text, links come with the text wrapped around them, scripts come with `src` and `integrity`, styles with their `href`. Nothing visual - no images, no fonts, no bytes - because that is not what an agent needs to reason about a page.

**`save_page`** - the `scan_page` pipeline, renamed and re-invented: the file lands in Downloads through `chrome.downloads.download({ saveAs: false })` straight from the service worker, so no "where do you want to save this?" dialog stops the caller. The agent receives the same manifest as before (filename, bytes, inlined counts, keptAssets, failures) - the human never sees an OS prompt.

The relay gained the matching primitive: `page.dump` is seeded on by migration `20261113000000_opera_methods_dump.sql`, the extension's `PROTOCOL` carries `page.dump: 20000`, and the MCP tool inventory stays at 41 tools over 36 primitives.

# WHAT CHANGED FOR CALLERS

- **`scan_page` is gone.** It is now `save_page`, and its behavior changed in one way that matters to everyone driving a device through the relay: the file is written to Downloads silently, no Save dialog. Anything coded against `scan_page` names the tool not found - call `save_page`.
- **Agents ask about a page they cannot see** without opening anything but `read_page`. `dump_page` fills the space between "scroll the viewport" and "download the whole file to disk": the page, as one structured object of text and structure, whether the question is "what is this page about", "where does this link go", or "which scripts run here".
- `dump_page` payload is small and paginated deliberately; the agent can page through a long text with `offset`/`limit` and `nextOffset` without blowing up its own context.

# WHAT IT COSTS THE READER

No visual, no image, no font. Everything that is not text and structure stayed out - `save_page` is the right tool when the reader wants the offline mirror, with all assets inlined as data URLs.
