# @title: 1.6.36 - one browser, one device, even when the extension is removed and installed again.
# @state: the release note for the version now shipping.
# @dependencies: none.

Every re-install of this extension used to register a new device row for the same browser. The per-profile id lived only in chrome.storage.local, and Chrome deletes that storage when the extension is removed, so each re-pair after a reinstall minted `opera-N` again with no relation to the previous one - while the dashboard kept the dead rows labelled online.

**The browser's cookie jar is the identity now, and re-pairing keeps the device.**

- The dashboard writes `oa_device_id` on first visit, one per browser profile, and the content script mirrors it into extension storage at document start on the paired site.
- At pair time the browser sends `cookieInstanceId` (`b:<the cookie>`) alongside its legacy storage identity.
- The hosted bridge forwards both; the new `opera_pair_device` overload matches the cookie identity first, and when no row holds it, adopts the legacy row **in place** - the cookie identity replaces the legacy one, the device keeps its name, and one browser keeps one device across reinstalls.
- A browser that never saw the cookie (cookie blocked, first pair since the upgrade) sends only the legacy identity and behaves exactly like the old build; the 9-argument overload is untouched for older bridges.
- Adoption is refused when the legacy row belongs to a different account; the name-clash suffixing path is unchanged.

**Limits, honestly.** The migration and the bridge deploy precede the extension re-pack; an account that re-pairs with 1.6.36 before the migration runs still mints a fresh row (the fallback is safe, not broken). The CRX for 1.6.36 is staged here and published by the owner; the stale device rows already in the dashboard (the `opera`, `opera-2` through `opera-5` rows from earlier re-pairing rounds) stay exactly as they are until the owner clears them.

An account can now remove and reinstall this extension as many times as it needs, and the dashboard will keep saying the truth: one browser, one device.
