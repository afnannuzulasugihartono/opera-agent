# WHAT REACHED THE BROWSER

**The local road can no longer be taken by a debugging port.** The extension
looked for the loopback bridge by asking "did anything answer on this port", and
a Chrome running with a remote debugging port answers on 9222. The extension
took it for a bridge, dialled a debugging endpoint forever, and reported "port
9222 discovered" while it never once linked - measured on the everyday machine,
with the real bridge one candidate away.

The probe now asks the bridge's own question, and a responder that cannot answer
it is not a bridge.

# WHAT REACHED THE SERVER

**The hosted road stopped waiting ten seconds for work the device had already
done.** The device completed a command in 414 ms, the function's own leg cost
about 950 ms, and the caller still waited about ten seconds - which is also how
calls began failing with `AWAIT_OUTCOME_UNKNOWN`.

The cause was the wait. The edge function reaches the database through
PostgREST, and both of its waits parked a PostgREST connection for as long as
the command took; a few calls in flight filled PostgREST's pool and every later
call queued behind them. The waits are now asked in short slices, so a
connection is held for a slice and not for a command, and the hosted road
answers in about 1.3 seconds where it answered in about ten.
